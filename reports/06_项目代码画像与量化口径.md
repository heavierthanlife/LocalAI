## 三、可直接算出的过程指标（第6章的数据基础）

系统在**建表层面**就埋好了流程测量点，这一点很少见也很值钱：

![流程数据模型与可算指标](figures/图13_流程数据模型与可算指标.png)

| 指标 | 计算口径 | 数据来源 |
|---|---|---|
| 流程周期 | `actual_end_date − actual_start_date`（天） | project_timelines |
| 计划偏差率 | `(实际周期 − 计划周期) / 计划周期` | project_timelines |
| 里程碑延误 | `diff_days`，及 `reason_category` 分布（延误归因） | project_timeline_milestones |
| 环节完成率 | `completed=true` 的 step 占比、按 `step_order` 的漏斗 | project_workflow_steps |
| 返工强度 | `revision_rounds`（修订轮次）、`generations`（生成次数） | workflow_kpi |
| 任务响应时长 | `AVG(done_at − created_at)`（小时） | project_todos |
| 审计耗时 | `AVG(completed_at − started_at)`（秒） | audit_runs |
| 质量水平 | `AVG(overall_score)`、`overall_status` 分布 | audit_runs |
| 文件版本迭代 | 每文件 `version` 数、`project_file_versions` 记录数 | project_files / project_file_versions |
| 过程留痕 | `admin_audit_log` 每项目记录数（可追溯性） | admin_audit_log |

**可直接跑的三条 SQL（字段名已核对 `database.py`）：**

```sql
-- ① 项目周期与计划偏差（上线前后可用 created_at 分组）
SELECT p.id,
       t.actual_end_date - t.actual_start_date                      AS cycle_days,
       t.planned_end_date - t.planned_start_date                    AS planned_days,
       (t.actual_end_date - t.actual_start_date)
       - (t.planned_end_date - t.planned_start_date)               AS delay_days
FROM projects p
JOIN project_timelines t ON t.project_id = p.id
WHERE t.actual_end_date IS NOT NULL;

-- ② 里程碑延误归因（论文里“流程冗余/外部脱节”的实证证据）
SELECT reason_category,
       COUNT(*)              AS n,
       AVG(diff_days)        AS avg_delay,
       STDDEV_POP(diff_days) AS sd_delay
FROM project_timeline_milestones
WHERE diff_days > 0
GROUP BY reason_category
ORDER BY n DESC;

-- ③ 返工强度与任务响应
SELECT AVG(revision_rounds) AS avg_revision,
       AVG(generations)     AS avg_generation,
       COUNT(*)             AS n_user_project
FROM workflow_kpi;

SELECT AVG(EXTRACT(EPOCH FROM (done_at - created_at)) / 3600.0) AS avg_hours
FROM project_todos WHERE done_at IS NOT NULL;
```

### 3. 生产数据可得性

能算指标 ≠ 你有数据。需要确认：
- 能否从生产库导**聚合结果**（上面三条 SQL 的输出，不需要明细、不含客户信息）；
- 系统里**有多少真实项目**（`SELECT count(*) FROM projects`）、时间跨度多长；
- 若项目数太少（<20），统计检验只能做描述性统计 + 案例对比，我会据此调整第6章的写法。
